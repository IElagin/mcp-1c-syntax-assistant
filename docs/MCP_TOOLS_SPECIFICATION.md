# ТЕХНИЧЕСКОЕ ЗАДАНИЕ: Реализация MCP инструментов для 1C-Syntax-Helper

## 1. ОБЩИЕ СВЕДЕНИЯ

**Версия:** 1.0  
**Дата:** 13.09.2025  
**Назначение:** Определение функциональности MCP инструментов для поиска по документации 1С  

## 2. ИСПРАВЛЕНИЕ ТИПОВ ДОКУМЕНТАЦИИ

### 2.1. Приведение в соответствие с doc_models.py

**Текущее состояние:**
- В `doc_models.py`: 9 типов включая `GLOBAL_EVENT`, `OBJECT_CONSTRUCTOR`
- В `mcp_models.py`: 6 типов, отсутствуют `GLOBAL_EVENT`, `OBJECT_CONSTRUCTOR`

**Требуется:**
```python
class DocumentationType(str, Enum):
    GLOBAL_FUNCTION = "global_function"
    GLOBAL_PROCEDURE = "global_procedure" 
    GLOBAL_EVENT = "global_event"
    OBJECT_FUNCTION = "object_function"
    OBJECT_PROCEDURE = "object_procedure"
    OBJECT_PROPERTY = "object_property"
    OBJECT_EVENT = "object_event"
    OBJECT_CONSTRUCTOR = "object_constructor"
    OBJECT = "object"
```

## 3. СПЕЦИФИКАЦИЯ MCP ИНСТРУМЕНТОВ

> Реализовано (см. `docs/superpowers/specs/2026-07-30-odnoznachnost-otvetov-design.md`):
> прежние пять инструментов с пересекающимися ролями сведены к трём
> несовпадающими. Два инструмента, различавшихся только детализацией
> технической информации, слились в `get_1c_element` (краткость — свойство
> списка, а не отдельной карточки); отдельный инструмент фильтрации по
> контексту исчез — его роль занял параметр `kind` у `find_1c_help`. Тексты
> описаний и JSON Schema ниже скопированы из `src/api/mcp_tools.py` — при
> расхождении источник истины он.

### 3.1. `find_1c_help` - Поиск по справке 1С

**Назначение:** Поиск по справке 1С, когда точное имя элемента неизвестно. Ищет по
русским и английским именам, описаниям и синтаксису. Возвращает список кандидатов
по одной строке на элемент. Полную карточку не возвращает — за ней вызывайте
`get_1c_element` с найденными именем и объектом. Если имя известно точно, вызывайте
`get_1c_element` сразу. Если нужен весь состав объекта — `list_1c_object_members`.

**Параметры:**
- `query` (string, обязательный) - Имя элемента, фрагмент имени или описание задачи
- `kind` (enum, опциональный, по умолчанию: `any`) - Чем ограничить поиск:
  `any`/`global`/`method`/`property`/`event`/`constructor`
- `object` (string, опциональный) - Искать только у этого объекта справки
- `limit` (integer, опциональный, по умолчанию: 10, от 1 до 200) - Сколько кандидатов вернуть

**Формат ответа** (реальный вывод, `find_1c_help(query="ТаблицаЗначений.Добавить", limit=5)`):
```
Найдено 1 элементов по запросу «ТаблицаЗначений.Добавить».

ТаблицаЗначений.Добавить — функция — ТаблицаЗначений.Добавить() — Добавляет строку в конец таблицы значений.

Полная карточка: get_1c_element(name=…, object=…)
```

При неуникальном имени вместо списка кандидатов в одну строку каждый вернётся
дизамбигуация — см. `get_1c_element` ниже.

---

### 3.2. `get_1c_element` - Полная карточка элемента

**Назначение:** Полная карточка элемента справки 1С: строка вызова, все варианты
вызова, параметры с типами и обязательностью, тип возвращаемого значения,
доступность по контекстам исполнения (тонкий клиент, сервер и прочие), версия
платформы, описание, примечание, пример. Требует точного имени. Если имя
встречается у нескольких объектов, вернётся список кандидатов вместо карточки —
повторите вызов, указав `object`. Для поиска по описанию используйте `find_1c_help`.

**Параметры:**
- `name` (string, обязательный) - Точное имя элемента, русское или английское
- `object` (string, опциональный) - Объект справки, которому принадлежит элемент —
  обязателен, если имя неуникально
- `variant` (string, опциональный) - Имя варианта вызова, если у элемента их
  несколько (например «По индексу»)

**Формат ответа** (реальный вывод, `get_1c_element(name="Добавить", object="ТаблицаЗначений")`):
```
ТаблицаЗначений.Добавить — функция объекта ТаблицаЗначений

Вызов: ТаблицаЗначений.Добавить()
Параметры: нет

Возвращает: СтрокаТаблицыЗначений
Доступность: сервер, толстый клиент, внешнее соединение, мобильное приложение (сервер), мобильный автономный сервер
Доступно с: 8.0

Описание: Добавляет строку в конец таблицы значений.
Пример:
  НоваяСтрока = ТаблицаЦен.Добавить();
  НоваяСтрока.Товар = ТекТовар;
  НоваяСтрока.Цена = ПолученнаяЦена;
```

**Ответ при неуникальном имени** (реальный вывод, `get_1c_element(name="Количество")`,
275 совпадений в индексе):
```
Имя «Количество» найдено у 275 элементов — карточка не может быть выбрана однозначно.
Уточните объект: get_1c_element(name="Количество", object="<объект>")

Наиболее вероятные:
  АгрегатыРегистраНакопления.Количество — функция — ...
  ВсеЭлементыФормы.Количество — функция — ...
  (ещё 3 кандидата)

Показано 5 из 275. За один вызов можно получить не более 200: find_1c_help(query="Количество", limit=200).
```

Отсутствующие данные карточка не замалчивает: «Доступность: в справке не указана»,
«Примеров в справке нет» и т.п. — вместо того, чтобы просто пропустить поле.

---

### 3.3. `list_1c_object_members` - Состав объекта

**Назначение:** Состав объекта 1С: методы, свойства, события, конструкторы, по
одной строке на элемент. Требует точного имени объекта из справки
(`МенеджерФоновыхЗаданий`, а не идентификатор из кода `ФоновыеЗадания`). Если
объект не найден, вернутся близкие по имени. За карточкой отдельного элемента —
`get_1c_element`.

**Параметры:**
- `object` (string, обязательный) - Имя объекта справки
- `members` (enum, опциональный, по умолчанию: `all`) - Какие элементы
  перечислить: `all`/`methods`/`properties`/`events`/`constructors`
- `limit` (integer, опциональный, по умолчанию: 100, от 1 до 1000) - Сколько
  элементов вернуть

**Формат ответа** (реальный вывод, `list_1c_object_members(object="ТаблицаЗначений", members="methods", limit=10)` — этот инструмент по-прежнему форматирует ответ через
`mcp_formatter.format_object_members_list`, декорированный эмодзи, а не через
единый рендер карточки/строки списка из §5 спеки):
```
📦 ОБЪЕКТ: ТаблицаЗначений

🔨 Методы (10):
   • Вставить (Insert)
     Вставляет строку на позицию в таблице значений, соответствующую указанному индексу.
   • Добавить (Add)
     Добавляет строку в конец таблицы значений.
   ...

⚠️ Показано 10 из 20. Остальные не выведены — повторите вызов с limit=20.
```

## 4. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

### 4.1. Обработка ошибок
- Все инструменты должны возвращать понятные сообщения об ошибках
- При отсутствии результатов предлагать альтернативные варианты поиска
- Логировать все запросы для мониторинга использования

### 4.2. Производительность  
- Время ответа каждого инструмента: < 500ms
- Кэширование частых запросов
- Ограничение размера ответов для предотвращения переполнения

### 4.3. Форматирование ответов
- Использование markdown для структурирования
- Эмодзи для визуального выделения разделов  
- Консистентная структура ответов всех инструментов
- Поддержка копирования синтаксиса в код

## 5. РЕАЛИЗАЦИЯ (историческая справка)

Этапы ниже описывали план по первоначальным пяти инструментам и относятся к
версии 1.0 этого документа (13.09.2025). Контракт с тех пор менялся дважды:
сначала реализован пятиинструментный вариант, затем (спека «однозначность
ответов», 2026-07-30) сведён к трём — `find_1c_help`, `get_1c_element`,
`list_1c_object_members` (см. §3 выше и §7 спеки). Названия методов
`find_help_by_query()`, `get_detailed_syntax_info()`, `search_with_context_filter()`,
`get_object_members_list()` — из первоначального плана; актуальные имена методов
сервиса поиска смотрите в `src/search/search_service.py`.

### Этап 1: Исправление моделей
1. Синхронизация `DocumentationType` в `mcp_models.py`
2. Создание моделей запросов для новых инструментов
3. Обновление базовых классов ответов

### Этап 2: Реализация search_service методов  
1. `find_help_by_query()` для универсального поиска
2. `get_detailed_syntax_info()` для технической информации
3. `search_with_context_filter()` для контекстного поиска
4. `get_object_members_list()` для элементов объекта

### Этап 3: Реализация MCP handlers
1. Создание обработчиков для каждого инструмента
2. Форматирование ответов согласно спецификации
3. Обработка ошибок и edge cases

### Этап 4: Интеграция и тестирование
1. Регистрация инструментов в FastAPI endpoints
2. Создание unit-тестов
3. Интеграционное тестирование с MCP клиентом

---

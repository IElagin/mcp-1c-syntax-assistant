# Инструменты MCP

Сервер объявляет три инструмента. Схемы ниже — те же словари, что лежат в
`src/api/mcp_tools.py` и отдаются клиенту в ответ на `tools/list`.

Разделение по назначению: `find_1c_help` ищет, когда имя неизвестно,
`get_1c_element` отвечает карточкой на точное имя, `list_1c_object_members`
перечисляет состав объекта. Прежние пять инструментов пересекались по смыслу, и
модель выбирала между ними наугад.

Как вызывать инструменты по HTTP и как подключить клиента — в
[CLIENT_SETUP.md](CLIENT_SETUP.md).

## find_1c_help

Поиск по справке, когда точное имя элемента неизвестно. Ищет по русским и
английским именам, описаниям и синтаксису. Возвращает список кандидатов по
одной строке на элемент, без полной карточки.

```json
{
  "type": "object",
  "properties": {
    "query": {
      "type": "string",
      "description": "Имя элемента, фрагмент имени или описание задачи"
    },
    "kind": {
      "type": "string",
      "enum": ["any", "global", "method", "property", "event", "constructor"],
      "default": "any"
    },
    "object": {
      "type": "string",
      "description": "Искать только у этого объекта справки"
    },
    "limit": {
      "type": "integer",
      "default": 10,
      "minimum": 1,
      "maximum": 200
    }
  },
  "required": ["query"],
  "additionalProperties": false
}
```

Значения `kind`:

| Значение | Что попадает в выдачу |
|---|---|
| `any` | Всё без ограничения по виду. |
| `global` | Глобальные функции, процедуры и события. |
| `method` | Методы объектов — функции и процедуры. |
| `property` | Свойства объектов. |
| `event` | События объектов. |
| `constructor` | Конструкторы. |

Лимиты — `SEARCH_LIMIT_DEFAULT = 10` и `SEARCH_LIMIT_MAX = 200` из
`src/api/mcp_tools.py`. Тот же потолок вшит в pydantic-модель запроса и в
подсказки «повторите с limit=N»: совет физически не может предложить число,
которое схема отвергнет.

`additionalProperties: false` — не украшение. Лишний аргумент отвергается с
ошибкой, а не отбрасывается молча: опечатка в имени параметра иначе
превращалась бы в поиск без фильтра, и агент получал бы не тот ответ, о котором
просил, не узнав об этом.

Пример ответа на `find_1c_help(query="FindRows", limit=3)`:

```
Найдено 9 элементов по запросу «FindRows».
Показано 3 из 9. Полный список: find_1c_help(query="FindRows", limit=9).

ДанныеФормыКоллекция.НайтиСтроки — функция — ДанныеФормыКоллекция.НайтиСтроки(<ПараметрыОтбора>) — Осуществляет поиск строк таблицы значений, отвечающих заданным условиям поиска.
ДанныеФормыСтруктураСКоллекцией.НайтиСтроки — функция — ДанныеФормыСтруктураСКоллекцией.НайтиСтроки(<ПараметрыОтбора>) — Осуществляет поиск строк таблицы значений, отвечающих заданным условиям поиска.
ВедущиеВидыРасчета.<Имя плана видов расчета>.НайтиСтроки — функция — ВедущиеВидыРасчета.<Имя плана видов расчета>.НайтиСтроки(<ПараметрыОтбора>) — Осуществляет поиск строк табличной части, соответствующих заданному условию поиска.

Полная карточка: get_1c_element(name=…, object=…)
```

Строка «Показано N из M» появляется, только когда выдача урезана. Параметра
смещения у инструмента нет, поэтому подсказка называет достижимый `limit`, а не
обещает «остальные элементы следующим вызовом» — повтор вернул бы те же первые.

## get_1c_element

Полная карточка элемента. Требует точного имени.

```json
{
  "type": "object",
  "properties": {
    "name": {
      "type": "string",
      "description": "Точное имя элемента, русское или английское"
    },
    "object": {
      "type": "string",
      "description": "Объект справки — обязателен, если имя неуникально"
    },
    "variant": {
      "type": "string",
      "description": "Имя варианта вызова, если у элемента их несколько"
    }
  },
  "required": ["name"],
  "additionalProperties": false
}
```

**`name` — имя элемента, а не полный путь.** Составное `Массив.Добавить` в
`get_1c_element` не найдётся: имя и объект передаются раздельно —
`name="Добавить"`, `object="Массив"`. Полный путь принимает `find_1c_help`.

Имя элемента можно писать по-русски или по-английски: `НайтиСтроки` и
`FindRows` равнозначны. Имя объекта — только по-русски: у страниц объектов
английского имени в справке нет.

## list_1c_object_members

Состав объекта: методы, свойства, события, конструкторы, по одной строке на
элемент.

```json
{
  "type": "object",
  "properties": {
    "object": {
      "type": "string",
      "description": "Имя объекта справки"
    },
    "members": {
      "type": "string",
      "enum": ["all", "methods", "properties", "events", "constructors"],
      "default": "all"
    },
    "limit": {
      "type": "integer",
      "default": 100,
      "minimum": 1,
      "maximum": 1000
    }
  },
  "required": ["object"],
  "additionalProperties": false
}
```

Лимиты — `MEMBERS_LIMIT_DEFAULT = 100` и `MEMBERS_LIMIT_MAX = 1000` из
`src/api/mcp_tools.py`.

Имя объекта берётся из справки и может не совпадать с идентификатором в коде:
менеджер фоновых заданий зовётся `МенеджерФоновыхЗаданий`, хотя в коде пишут
`ФоновыеЗадания`.

Пример ответа на `list_1c_object_members(object="ТаблицаЗначений",
members="methods", limit=5)`:

```
Состав объекта ТаблицаЗначений.

Методы (5):
  ТаблицаЗначений.Вставить — функция — ТаблицаЗначений.Вставить(<Индекс>) — Вставляет строку на позицию в таблице значений, соответствующую указанному индексу.
  ТаблицаЗначений.ВыбратьСтроку — функция — ТаблицаЗначений.ВыбратьСтроку(<Заголовок>, <НачальнаяСтрока>) — Вызывает модальное диалоговое окно для интерактивного выбора строки из таблицы значений.
  ТаблицаЗначений.ВыгрузитьКолонку — функция — ТаблицаЗначений.ВыгрузитьКолонку(<Колонка>) — Создает массив и копирует в него значения, содержащиеся в колонке таблицы значений.
  ТаблицаЗначений.Добавить — функция — ТаблицаЗначений.Добавить() — Добавляет строку в конец таблицы значений.
  ТаблицаЗначений.ЗагрузитьКолонку — процедура — ТаблицаЗначений.ЗагрузитьКолонку(<Массив>, <Колонка>) — Загружает колонку таблицы значений из массива значений.

Показано 5 из 20. Полный список: list_1c_object_members(object="ТаблицаЗначений", members="methods", limit=20).
Полная карточка: get_1c_element(name=…, object="ТаблицаЗначений")
```

Конструкторы запрашиваются тем же инструментом:

```
Состав объекта ТаблицаЗначений.

Конструкторы (1):
  ТаблицаЗначений.По умолчанию — конструктор — Новый ТаблицаЗначений

Полная карточка: get_1c_element(name=…, object="ТаблицаЗначений")
```

## Формат карточки элемента

Карточка отвечает на два вопроса: что вызывать и как вызывать. Поэтому у неё
фиксированный набор полей, и отсутствие данных помечается явно — пропущенное
поле неотличимо от «данных нет», и модель достраивает пробел домыслом.

Для функции, процедуры и события:

| Строка | Когда данных нет |
|---|---|
| Заголовок: полный путь, вид элемента, объект-владелец | — |
| `Вызов:` — строка вызова со списком параметров | `Вызов: в справке не указано` |
| `Параметры:` — имя, тип, обязательность, описание | `Параметры: нет` |
| `Описание варианта:` — пояснение к конкретному варианту вызова (не то же самое, что общее `Описание:` элемента ниже); своя строка на каждый вариант, где справка дала такое пояснение | Строка не печатается |
| `Возвращает:` — тип и пояснение | `Возвращает: нет (процедура)` либо `Возвращает: в справке не указано` |
| `Доступность:` — контексты исполнения через запятую | `Доступность: в справке не указана` |
| `Доступно с:` — версия платформы | Строка не печатается |
| `Описание:` | `Описание: в справке отсутствует` |
| `Примечание:` | Строка не печатается |
| `Пример:` — код | `Примеров в справке нет.` |

Обязательность параметра различает три состояния: `обязательный`,
`необязательный` и `обязательность в справке не указана`. Последнее — не то же
самое, что «необязательный».

Если у элемента несколько вариантов вызова, перед ними — сразу за заголовком
карточки — печатается строка `Вариантов вызова: N`, и каждый вариант идёт своим
блоком с именем. Нужен один — передайте `variant`.

У свойства другой набор полей: вместо `Вызов:` печатается `Обращение:`, а
вместо параметров и возвращаемого значения — `Тип значения:` и `Доступ:`.
Свойство не вызывают, к нему обращаются, и по ярлыку агент понимает, ставить ли
скобки. Вывод `get_1c_element(name="Колонки", object="ТаблицаЗначений")`:

```
ТаблицаЗначений.Колонки — свойство объекта ТаблицаЗначений

Обращение: ТаблицаЗначений.Колонки
Тип значения: КоллекцияКолонокТаблицыЗначений
Доступ: только чтение
Доступность: сервер, толстый клиент, внешнее соединение, мобильное приложение (сервер), мобильный автономный сервер
Доступно с: 8.0

Описание: Содержит коллекцию колонок таблицы значений.
Примеров в справке нет.
```

Карточка объекта не перечисляет членов — их бывают сотни, и урезанный список
дал бы ту же молчаливую неполноту. Вместо списка печатаются строки вызова
конструкторов, число методов, свойств и событий и готовый вызов
`list_1c_object_members`:

```
ТаблицаЗначений — объект

Конструкторы:
  Новый ТаблицаЗначений
Доступность: сервер, толстый клиент, внешнее соединение, мобильное приложение (сервер), мобильный автономный сервер
Доступно с: 8.0

Описание: Таблица значений предназначена для хранения значений в табличном виде. Все основные операции с таблицей производятся именно через этот объект. Он позволяет манипулировать строками таблицы значений и предоставляет доступ к коллекции колонок. Колонки могут быть различных типов (в том числе множественных).
Состав — методов: 20, свойств: 2, событий: 0.
Перечень: list_1c_object_members(object="ТаблицаЗначений")
```

Если под этим именем в индексе нет ни одного члена, карточка так и пишет:
запрашивать нечего. Совет `list_1c_object_members` печатается только тогда,
когда по тому же ключу действительно есть что перечислять — иначе он вёл бы в
тупик «объект в справке не найден».

## Поведение при неуникальном имени

Имя `Добавить` встречается на 197 страницах справки. Выдать одну из них за
ответ значило бы соврать, поэтому вместо карточки приходит перечень кандидатов:

```
Имя «Добавить» найдено у 197 элементов — карточка не может быть выбрана однозначно.
Уточните объект: get_1c_element(name="Добавить", object="<объект>")

Кандидаты (сначала типы языка, внутри — объекты с бо́льшим числом элементов в справке):
  XBase.Добавить — процедура — XBase.Добавить() — Добавляет новую пустую запись. При этом поля и свойства объекта Ключ очищаются. …
  СписокЗначений.Добавить — функция — СписокЗначений.Добавить(<Значение>, <Представление>, <Пометка>, <Картинка>) — Добавляет новый элемент в конец списка значений.
  ТаблицаЗначений.Добавить — функция — ТаблицаЗначений.Добавить() — Добавляет строку в конец таблицы значений.
  ХранилищеСертификатовКриптографии.Добавить — процедура — ХранилищеСертификатовКриптографии.Добавить(<Сертификат>) — Добавляет сертификат в хранилище.
  ФорматированныйДокумент.Добавить — функция — ФорматированныйДокумент.Добавить(<Значение>, <ТипЭлемента>) — Добавляет строку, картинку или перевод строки в конец форматированного документа.

Показано 5 из 197. Полный список: find_1c_help(query="Добавить", limit=197).
```

Заголовок называет порядок, а не обещает вероятность: «сначала типы языка,
внутри — объекты с бо́льшим числом элементов». Это не ранжирование по
релевантности, и выдавать его за таковое нельзя.

Если кандидатов слишком много, чтобы упорядочить их одним запросом, к перечню
добавляется строка «порядок построен не по всем совпадениям».

## Поведение при отсутствии данных

Сервер различает четыре причины пустого ответа и называет каждую своими
словами.

**Элемент не найден.** Печатается похожее по имени, если такое есть:

```
Элемент с точным именем «Массив.Добавить» в справке не найден.
Похожих по имени тоже нет — проверьте написание.
```

**Объект не найден** — тогда искать элемент негде, и сервер говорит об этом
прямо, а не отвечает «элемент не найден»:

```
Объект «Array» в справке не найден, поэтому элемент «Add» у него искать негде. Похожие объекты: подходящих не найдено.
Имя объекта в справке может отличаться от идентификатора в коде: например, менеджер фоновых заданий зовётся МенеджерФоновыхЗаданий.
```

**Вариант вызова не найден** — перечисляются те, что есть:

```
Варианта «Пятый» у элемента «Добавить» нет. Доступные варианты: вариант единственный и без имени.
```

**Поиск не дал совпадений** — сервер объясняет, что именно он проверил, и
предлагает следующий шаг:

```
По запросу «ValueTable.Add» ничего не найдено.
Ни фильтра по объекту, ни фильтра по виду не было — совпадений нет во всей справке. Что можно сделать: проверить имя по-русски и по-английски; поискать по словам из описания; если известен объект — посмотреть его состав через list_1c_object_members.
```

Если фильтры были заданы, формулировка называет их: сервер не утверждает
отсутствие данных, которых не проверял.

Сбой Elasticsearch не маскируется под «не найдено»: он возвращается как ошибка
с `isError: true`, чтобы обрыв связи нельзя было принять за честный пустой
ответ.
